# Pywal16 + mako Integration Guide

## Overview

This guide explains how to configure **mako** (Wayland notification daemon) to sync its color theme with wallpaper changes via pywal16, while keeping your static mako config (layout, timeouts, urgency rules, keybinds) untouched by every `wal` run.

### What This Achieves

- **mako's background/text/border colors** automatically match wallpaper
- **Everything else** (layout, per-urgency timeouts, per-app rules, mouse bindings) lives in a normal, hand-edited config file that pywal never touches
- Updates happen automatically when you run `wal -i image.png`
- Note: Want the sway compositor itself themed too? See `colors-sway`, already in this repo
- Note: Want the standalone `cava` binary or rmpc's Cava pane themed? See [RMPC_SETUP.md](RMPC_SETUP.md) and [CAVA_SETUP.md](CAVA_SETUP.md)

### Why Split Colors From Config

Unlike rmpc (which hot-reloads a single generated file), mako's config format supports a native `include=` directive. That means the *generated* half can stay tiny and disposable — exactly like pywal16's existing minimal templates for other apps — while your actual mako behavior config stays a normal, permanent, hand-edited file that `wal` never overwrites.

## Quick Start

### 1. Ensure pywal16 is Installed

```bash
which wal
wal --version
```

### 2. Ensure mako is Installed

```bash
which mako
mako --version
```

### 3. Confirm the Color Template Exists

This repo already ships a minimal color template at `pywal/templates/colors-mako`:

```ini
background-color={background}
text-color={foreground}
border-color={color1}
```

Nothing to add here unless you want to extend the palette mapping later (see [Customization](#customization)).

### 4. Create Your Static mako Config

Unlike the generated color file, `~/.config/mako/config` is a **real file you edit directly** — not a symlink. It pulls in the generated colors via `include=`:

```ini
# ~/.config/mako/config
# Static config — colors come from the include below.
# This file is NOT regenerated by wal; edit it freely.

include=~/.cache/wal/colors-mako

# --- Global behavior ---
max-history=20
sort=-time
default-timeout=8000
ignore-timeout=0

# --- Layout / position ---
layer=overlay
anchor=top-right
outer-margin=10
margin=5
padding=10,15
width=350
height=120
border-size=2
border-radius=6

font=JetBrains Mono 10

# --- Icons ---
icons=1
max-icon-size=48
icon-location=left

# --- Grouping ---
group-by=app-name

# --- Mouse bindings ---
on-button-left=dismiss
on-button-middle=invoke-default-action
on-button-right=dismiss-all
on-touch=dismiss

# --- Per-urgency overrides (non-color) ---
[urgency=low]
default-timeout=4000

[urgency=critical]
default-timeout=0

# --- Per-app overrides (non-color) ---
[app-name="weather"]
default-timeout=10000
```

Per `man 5 mako`, `include=` accepts a path starting with `~/` (not `$HOME` — that's not expanded). `~/.cache/wal/colors-mako` above works as-is, no username hardcoding needed.

### 5. Generate Initial Theme

```bash
wal -i ~/Images/Wallpaper/your-image.png
```

### 6. Reload mako

mako does **not** hot-reload on file changes — reload manually or via a hook:

```bash
makoctl reload
```

## How It Works

### Two Files, Two Lifecycles

| File | Regenerated by `wal`? | What it contains |
|---|---|---|
| `~/.cache/wal/colors-mako` | Yes, every run | 3 lines: background, text, border color |
| `~/.config/mako/config` | No — static | Everything else: layout, timeouts, urgency/app rules, `include=` line |

**Generated file** (`~/.cache/wal/colors-mako`), example output:

```ini
background-color=#130c1b
text-color=#c4c2c6
border-color=#28373d
```

mako reads this via the `include=` line at the top of your static config. `include=` is a flat merge, so put it first: mako parses top-to-bottom, and a later `border-color=` in a `[urgency=...]`/`[app-name=...]` block overrides the included value, but only within that block's scope, not globally.

### No Auto-Reload

Same caveat as always: mako doesn't watch its config for changes. Run `makoctl reload` after `wal`, or better, hook it in — see [Extending with Hooks](#extending-with-hooks).

## Customization

### Extend the Color Template

If you want more than one themed color (say, a distinct color for critical urgency), add more variables to `pywal/templates/colors-mako`:

```ini
background-color={background}
text-color={foreground}
border-color={color1}
critical-color={color1}
low-color={color8}
```

Then reference the *named* keys mako actually supports inside your static config's blocks. Note: mako's per-section syntax expects real property names like `border-color=`, not arbitrary custom keys — so `critical-color` above isn't valid mako syntax on its own. To get a distinct critical-urgency color from the palette, set it directly on the section:

```ini
[urgency=critical]
border-color={color1}
default-timeout=0
```

But since `{color1}` is a template variable, this line must live in the **template** (`colors-mako`), not the static config — the static config only ever sees literal hex once `wal` has rendered it. In practice this means: if you want palette-driven, per-urgency colors, the `[urgency=...]` blocks with color overrides need to move into `colors-mako` itself, and only non-color rules (timeouts, grouping) stay in the static file. This is the trade-off of the split approach — pick whichever side gets a given setting based on whether it should ever change color with the wallpaper.

### Adjust Background Opacity

Add an alpha suffix directly in the template:

```ini
background-color={background}ee
```

Regenerate: `wal -i image.png`

### Adjust Which Palette Colors Map Where

Edit `pywal/templates/colors-mako` — any `{colorN}`, `{background}`, or `{foreground}` can go on any line:

```ini
border-color={color4}
```

## Troubleshooting

### mako Reports Config Errors / Won't Start

**Cause**: `include=` path is wrong, or the generated file doesn't exist yet

**Solution**:

```bash
wal -i ~/Images/Wallpaper/image.png
ls -la ~/.cache/wal/colors-mako
mako   # run in foreground to see the actual parse error
```

### `include=` Line Rejected or Ignored

**Cause**: `include=` requires the file to actually exist yet, or the path isn't `~/`-prefixed or absolute (mako does not expand `$HOME`).

**Solution**: Confirm the file exists (`ls -la ~/.cache/wal/colors-mako`) and that the `include=` line reads exactly `include=~/.cache/wal/colors-mako`.

### Colors Not Updating When I Run `wal`

**Cause**: `makoctl reload` isn't being called

**Solution**:

```bash
makoctl reload
cat ~/.cache/wal/colors-mako   # confirm new hex values are actually there first
```

If the generated file has new colors but notifications look stale, the reload step is what's missing — wire it into your post-hook (below).

### My Static Config Edits Keep Getting Reset

**Cause**: If you're still using the old symlink-the-whole-file approach from an earlier setup, `~/.config/mako/config` may still be a symlink to the cache file, so every `wal` run replaces the whole thing.

**Solution**:

```bash
ls -la ~/.config/mako/config
# If it shows "-> /home/.../cache/wal/...", it's still a symlink

rm ~/.config/mako/config
# Recreate as a real file per Quick Start step 4 above
```

### Per-App Override Not Applying

**Cause**: `app-name` must match what the app reports via D-Bus.

**Solution**:

```bash
notify-send -a "weather" "Test" "Checking app-name match"
makoctl history
```

### Critical Notifications Look Muddy / Low Contrast

**Cause**: Some generated palettes lack a strong high-contrast color at `{color1}`.

**Solutions**:

1. Try a different wallpaper: `wal -i different-image.png`
2. Increase contrast: `wal -i image.png --contrast 2.0`
3. Hardcode a fixed hex for that one line in the template instead of a palette variable

## Extending with Hooks

Want one script that reloads sway/mako/kitty/ghostty/rmpc and syncs cava's config together, instead of hand-rolling your own? See [`Integrations/wal-reload.sh`](wal-reload.sh) — usable via `-o` the same way as the standalone example below. (waybar isn't signaled by default — see the script's header comment on `swaybar_command` vs. plain `exec waybar`.)

### Run Custom Script After `wal`

```bash
wal -i image.png -o ~/.local/bin/wal-post-hook.sh
```

**Example hook** (`~/.local/bin/wal-post-hook.sh`):

```bash
#!/bin/bash
# Run after wal generates colors

makoctl reload
pkill -HUP rmpc
swaymsg reload

echo "Pywal update complete!"
```

```bash
chmod +x ~/.local/bin/wal-post-hook.sh
```

### Alternative: Systemd User Timer

For periodic wallpaper changes, reuse the same pattern as [RMPC_SETUP.md](RMPC_SETUP.md#alternative-systemd-user-timer) — the hook above already covers mako's reload, so no mako-specific timer is needed.

## Files

### Generated Files

- `~/.cache/wal/colors-mako` — 3-line color-only theme, regenerated every `wal` run
- `~/.cache/wal/colors.json` — full palette
- `~/.cache/wal/sequences` — terminal escape sequences

### Static Files (never touched by `wal`)

- `~/.config/mako/config` — real file, includes the generated colors, holds everything else

### Template (in pywal16 repo)

- `pywal/templates/colors-mako` — 3-line source template for the generated color file
