# Pywal16 Development Guide

## Quick Start

### Setup
```bash
git clone https://github.com/eylles/pywal16.git
cd pywal16
uv venv .env
. .env/bin/activate
uv pip install -e .
uv pip install pytest flake8 pylint
```

### Run Tests
```bash
python tests/test_colors.py
python tests/test_export.py
python tests/test_sequences.py
python tests/test_util.py
```

### Try It Out
```bash
wal -i ~/path/to/image.png
wal --preview
ls ~/.cache/wal/colors-*
```

## Architecture Overview

### High-Level Color Pipeline
```
Image Input
    ↓
[Color Backend: wal, colorz, colorthief, etc.]
    ↓
[Generate 16-color Palette]
    ↓
[Color Dictionary: {special: {...}, colors: {...}}]
    ↓
[Export Templates] → ~/.cache/wal/colors-*.conf
    ↓
[Terminal Sequences] → OSC codes to terminal
    ↓
[Reload Apps] → Signal i3, sway, polybar, etc.
    ↓
[Optional Hooks] → Run external scripts
```

### Core Modules

| Module | Purpose |
|--------|---------|
| `colors.py` | Color generation from images/backends |
| `image.py` | Image selection & caching |
| `export.py` | Template processing (Jinja2-like syntax) |
| `sequences.py` | Terminal escape sequences (OSC-4) |
| `wallpaper.py` | DE wallpaper setting (feh, nitrogen, swaybg, etc.) |
| `reload.py` | App signaling (i3, polybar, kitty, etc.) |
| `theme.py` | Theme management & loading |
| `util.py` | Color class & utilities |
| `backends/` | Color extraction algorithms |

### Configuration

**Environment Variables:**
- `XDG_CONFIG_HOME` — Config dir (default: `~/.config`)
- `XDG_CACHE_HOME` — Cache dir (default: `~/.cache`)
- `PYWAL_CACHE_DIR` — Override cache location

**Default Paths:**
- Config: `~/.config/wal/templates/`, `~/.config/wal/colorschemes/[light|dark]/`
- Cache: `~/.cache/wal/` (colors.json, sequences, exported templates)

## Common Development Tasks

### Add a Color Backend

1. Create `pywal/backends/mybackend.py`:
```python
def get(image, light=False):
    """Extract colors from image."""
    # ... your algorithm ...
    return [
        "#FF0000",
        "#00FF00",
        # ... 8 more hex colors
    ]
```

2. Add to `backends/__init__.py`:
```python
from .mybackend import get as mybackend
```

3. Test:
```bash
wal --backend mybackend -i image.png
```

### Add an Export Template

1. Create `pywal/templates/colors-myapp.conf`:
```
# Generated by pywal16
foreground={foreground}
background={background}
color0={color0}
color1={color1}
# ... etc
```

2. Run pywal:
```bash
wal -i image.png
```

3. Check output:
```bash
cat ~/.cache/wal/colors-myapp.conf
```

**Template Variables Available:**
- Colors: `{color0}` ... `{color15}`
- Special: `{background}`, `{foreground}`, `{cursor}`
- Wallpaper: `{wallpaper}`
- Color transforms: `{color0.rgb}`, `{color0.hex}`, `{color0.darken(0.1)}`

### Add WM/App Reload

Edit `pywal/reload.py`:

```python
def myapp():
    """Reload myapp colors."""
    if shutil.which("myapp") and util.get_pid("myapp"):
        util.disown(["myapp-signal-reload"])
```

Then call from `env()`:
```python
def env(xrdb_file=None, tty_reload=True):
    # ... existing calls ...
    myapp()
    # ...
```

# All tests
python -m pytest tests/

## Design Principles

1. **Modularity** — Each module has one job
2. **Extensibility** — Backends, templates, reload functions can be added without touching core
3. **Graceful Degradation** — Missing tools/backends don't crash, just skip that part
4. **Cross-Platform** — Support Linux (X11/Wayland), macOS, Windows
5. **Runtime Detection** — Detect available tools at runtime, don't hard-code

## Debugging

### Enable Verbose Output
```bash
# Stderr shows INFO/DEBUG messages
wal -i image.png 2>&1 | grep -E "^\[I\]|\[D\]"
```

### Inspect Generated Data
```bash
# Last generated palette
cat ~/.cache/wal/colors.json | jq .

# Terminal sequences
cat ~/.cache/wal/sequences

# All exported templates
ls -la ~/.cache/wal/colors-*
```

### Test Color Class
```python
from pywal.util import Color
c = Color("#FF0000")
print(c.hex, c.rgb, c.darken(0.2))
```

### Test Template Processing
```bash
# After running wal, check a template was processed correctly
cat ~/.cache/wal/colors-rmpc-theme.ron
```

## Release Process

1. Update version in `setup.py`
2. Run full test suite: `python -m pytest tests/`
3. Test key workflows on Linux/macOS if possible
4. Tag release: `git tag -a v3.8.15 -m "Release 3.8.15"`
5. Push: `git push origin main && git push origin v3.8.15`
6. Update AUR package (see ARCH_PACKAGING.md)
